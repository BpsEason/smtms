# SMTMS 專案 AI 開發規則

## 最小固定 Context 讀取
開始任何任務時，使用 Read 工具讀取 `.ai/instructions.md` 取得必要的基本規則。TRAE 不會自動載入此文件，必須手動讀取。

## 按需讀取 Context 文件
根據任務性質，僅讀取必要的 Context 文件：
- `.ai/architecture.md`：涉及模組關係、系統架構或跨模組修改時才讀取
- `.ai/business_rules.md`：涉及業務流程、資料一致性或業務限制時才讀取
- `.ai/project_state.md`：需要了解目前實作狀態、已知限制或既有待辦時才讀取
- `.ai/task_template.md`：需要建立較完整的任務指令時才讀取
- 與任務無關的 Context 文件不要讀取

## 工作流程約束
1. **最小搜尋範圍**：永遠先從相關模組開始搜尋
2. **避免重複讀取**：優先沿用本次對話中已經取得且仍然有效的資訊，只有在資訊缺失、過時或需要確認實際實作時，才重新讀取相關文件或程式碼，不要為了遵守規則而無條件重讀所有 Context 文件
3. **依賴逐步擴展**：沿著依賴鏈逐步擴大查詢範圍
4. **優先使用現有工具**：優先使用SearchCodebase、Read等工具，不要任意執行全域搜尋命令

## 與既有文件的關係
- Context 摘要不能取代正式規格、實際程式碼、資料庫結構及設定
- 正式文件都在`docs/`目錄下，.ai/目錄僅用於AI Coding Context管理
- 所有業務規則、架構描述以docs/的正式文件為準，.ai/只是摘要整理
- 修改既有功能時，依任務需要確認相關實作與正式規則
- 更新正式文件時，一併更新.ai/對應的摘要文件
- 不確定時先查證，不可因為 Context 不完整而自行推測

## 禁止事項
1. 不得修改業務程式碼、資料庫結構除非任務明確要求
2. 不得安裝新的依賴套件
3. 不得為了省Token省略必要的測試和驗證步驟
4. 不得假設不存在的功能或欄位，必須查證後再使用
